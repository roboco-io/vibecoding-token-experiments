# EXP-002 설계: 한국어 vs 영어 파이프라인 토큰 비교

- 일자: 2026-07-21
- 상태: 승인됨 (심층 인터뷰 후 확정)

## 배경

한국어는 Claude 토크나이저에서 같은 의미 표현에 영어보다 1.5~2.5배 토큰을 사용한다. EXP-001 분석에서 output(에이전트 생산 텍스트)과 cache_creation(재독 편입)이 billable의 대부분을 차지함을 확인 — 작업 언어가 실질 비용 변수일 가능성.

## 인터뷰 결정 사항

| 질문 | 결정 | 기각한 대안과 사유 |
|------|------|-------------------|
| 언어 적용 범위 | **전 파이프라인** (프롬프트 + 산출 문서·주석·커밋·보고 언어 강제) | 프롬프트만: 에이전트가 자율적으로 영어 작업 시 효과 희석. 3조건(KO→EN 분리): 비용 1.5배, 1차 실험에서는 과함 |
| 과제·워크플로 | **RealWorld + ralph 1세션** (EXP-001 재사용) | 축소 과제: 문서량이 적어 언어 효과가 작게 나올 우려 |
| 반복 수 | **n=2** (조건당 2회, 총 4 run ~130만 토큰) | n=1: 노이즈 구분 불가. n=3: 비용 대비 한계 효용 |
| 정적 측정 | **포함** (count_tokens로 KO/EN 문서쌍 비율 = 해석 기준선) | — |

## 설계 요점

- 조건: KO / EN, 언어 외 내용 동일한 프롬프트 쌍 (실행 전 교차 검토)
- EXP-001 ralph 실행은 언어 지시 부재로 KO 조건 재사용 불가 → 4회 신규 실행
- 완료 판정 사전 고정: Hurl 154요청 (EXP-001의 테스트 정본 불일치 교훈 반영)
- run 교차 배치(ko-1→en-1→ko-2→en-2), run별 독립 리포로 로그 슬러그 분리
- 언어 준수 검사 실패 run은 무효·재실행
- 판정 규칙: |KO평균 − EN평균| > 조건 내 run 간 변동폭
