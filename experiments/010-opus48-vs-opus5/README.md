# EXP-010 설계: Opus 4.8 vs Opus 5 순수 A/B (동일 시점·동일 하네스)

## 배경

EXP-009는 Opus 5의 "산출량 확대 프로파일"(output +62%·커밋 2배·시간 증가)을 발견했으나, 비교 대상인 Opus 4.x 데이터가 **3일 전(2026-07-24) 실행·구형 하네스(게이트/iteration 채점 없음)**라는 한계가 있었다. 본 실험은 두 모델을 **같은 날, 같은 하네스, 교차 순서**로 실행해 세대 차가 시점·계측 아티팩트가 아님을 검증한다.

## 가설

[M-06](../../hypotheses/catalog.md) — 완전 동일 조건에서 Opus 5는 Opus 4.8 대비 EXP-009의 프로파일 차이(output 토큰·커밋 수 증가, wall-clock 증가)를 재현하며, 두 모델 모두 단일 세션 완주를 유지한다.

## 조건 (사전 고정)

- **모델**: `claude-opus-4-8` (EXP-002 실사용 ID, 로그 검증) vs `claude-opus-5`. 각 n=3
- **실행 순서**: 48-1 → 5-1 → 48-2 → 5-2 → 48-3 → 5-3 (교차 — 시간대·서빙 상태 효과 분산), 단일 드라이버가 순차 실행 (포트 충돌 원천 차단)
- **동일 요소**: PROMPT.md byte-identical(EXP-002 en 정본), 하네스(상한 10 iter, `.ralph-done` 게이트, iteration별 Hurl 채점, 포트 자동 탐지), 기본 `~/.claude` 환경, run별 독립 빈 리포, caffeinate + 터미널 분리 기동
- **판정 기준 (사전 등록)**:
  - 완주: 양 모델 각 3/3 단일 세션 완주 기대 (미완주 발생 시 해당 모델 특성으로 기록)
  - **프로파일 재현(검증)**: output 토큰과 git 커밋 수의 모델 간 분포가 겹치지 않고 방향이 EXP-009와 동일(5 > 4.8)
  - **기각**: 두 지표 분포가 겹침 — EXP-009의 차이는 시점/계측 아티팩트였다는 뜻
  - wall-clock·API 호출 수·도구 분포는 보조 지표 (EXP-009에서 변동성 확인됨)
- 비용·언어(L축)는 판정에 미사용

## Phase 0 (통과 기록)

1. `claude-opus-4-8` 스모크 응답 확인 (EXP-002 이후에도 서빙 유지)
2. PROMPT diff 0 (EXP-009 정본과 동일)
3. measure.sh = EXP-009판 경로 치환본, 포트 8000 비점유
4. metrics 6개 사전 생성 (모니터 tail 안정성)

## 리스크

- 4.8이 구모델 서빙 축소로 속도 특성이 EXP-002 당시와 다를 수 있음 — 그 자체가 "동시점 비교"의 측정 대상
- n=3/모델은 완주율·프로파일 방향 판별용이며 효과 크기의 정밀 추정에는 부족
