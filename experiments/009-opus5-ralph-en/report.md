# EXP-009 결과 보고: Opus 5 랄프 루프 (EXP-002 en 조건, n=3)

- 실험일: 2026-07-27
- 가설: [M-05](../../hypotheses/catalog.md) — Opus 5는 EXP-002 en 조건의 랄프 루프에서 단일 세션 완주를 재현하고, Opus 4.x 기준선(en 6–7분·API 38–54회) 대비 동등 이상의 효율을 보인다.
- **판정: 부분 검증 (n=3)** — 완주 조항 검증: **3/3 run 모두 iteration 1 단일 세션 완주**(9분03초–12분22초, 게이트 13/13·154/154 + 독립 재검증 각 2회, 커밋 6–7개). 효율 조항 미충족 확정: 시간 분포(8.9–12.2분)가 4.x(5.8–6.9분)와 비겹침 — 단 원인은 서빙 속도가 아니라 **일관된 산출량 증가(+62%)를 동반한 행동 프로파일 변화**로 판별됨.

## 판별 분석: 프로파일 차이인가, run 간 변동인가 → **프로파일 차이**

| 지표 | 4.x (n=2) | 5 (n=3) | 겹침 | 해석 |
|------|-----------|---------|------|------|
| **output 토큰** | 25.3–31.7K | **42.6–48.4K** | **없음** (+62%, run 간 변동 ±7%) | **가장 안정적인 세대 시그니처** — 코드+문서+검증 서사를 더 많이 생성 |
| wall-clock | 5.8–6.9분 | 8.9–12.2분 | 없음 (+70% 평균) | 일관된 증가 — 변동으로 설명 불가 |
| 호출당 지연 | 8.4–9.4초 | 8.3–12.4초 | **있음** (run-2 = 8.3초) | **"서빙이 느리다" 기각** — 호출당 속도는 4.x 수준까지 내려감 |
| API 호출 수 | 41–44 | 43–84 | 있음 (run-3 = 43) | 변동 큼 — 경로(재읽기·수정 횟수)는 run마다 다름 |
| 커밋 수 | 2–3 | 6–7 | 없음 | 일관된 규율 강화 |
| Read 호출 | 2–4 | 0–15 | 있음 | 검증 경로는 가변 (run-3은 Read 0으로도 완주) |

결론: 시간 증가는 **무엇을 얼마나 만드는가(산출량·커밋 규율)의 일관된 변화**에서 오고, **어떤 경로로 가는가(호출 수·재읽기)는 run 간 변동**이다. 겹치지 않는 지표(output·시간·커밋)와 겹치는 지표(지연·호출 수)가 깨끗이 갈려, n=3으로도 판별이 성립한다.

## 관찰

1. **"더 느리게, 더 완전하게"는 재현되는 프로파일이다.** 3 run 모두 시키지 않은 README 문서화·완료 기준 재검증 커밋을 수행했고, 최속 run(9분)조차 커밋 7개를 남겼다. 4.x의 최단 경로형과 대비되는 세대 특성.
2. **경로 다양성 속의 결과 안정성.** run-3은 Read 0회·hurl 14회(테스트 주도), run-1은 Read 15회(재독 주도)로 전략이 달랐지만 세 run 모두 iteration 1 완주·13/154·커밋 6+ — 결과 분산이 과정 분산보다 훨씬 작다.
3. **랄프 루프 인프라(게이트·iteration 채점)는 3 run 연속 무발동** — 강한 모델에서 루프는 보험으로만 기능한다는 EXP-009 초기 관찰이 유지됐다.

## 결론·후속
