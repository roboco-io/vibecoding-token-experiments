# EXP-016 설계: n=1 완주 조건 3종의 재현성 확충 (각 n=3)

## 배경

EXP-011(Codex CLI × gpt-5.6-sol)·EXP-013(qwen3.8-max 직결)·EXP-014(kimi-k3 직결)는 모두 iteration 1 완주였으나 n=1이라 재현성(완주율) 서사가 불가능했다(각 report 한계 절). 본 실험은 세 조건에 **run 2·3을 추가해 각 n=3**을 만들고 완주율을 판정한다. 원 실험 report는 수정하지 않는다 — 확충 판정은 본 실험이 담당한다.

## 가설

[M-12](../../hypotheses/catalog.md) — EXP-011/013/014 세 조건의 무개입 완주는 재현된다: 각 조건 추가 2 run(총 n=3)이 모두 상한 30 iteration 안에 게이트(Hurl 13/13·154/154)+독립 재검증 일치로 완주한다. (과금 배제 — 완주율 단일 판정)

## 조건 (사전 고정)

- **각 조건은 원 실험과 동일**: 하네스 베이스(`~/ralph-exp011/013/014`)·driver(RUN명만 치환)·PROMPT(EXP-010 정본 byte-identical)·env(effort medium / thinking 기본값)·격리·상한 30 iter 그대로
- **실행 방식**: **순차 실행** (동시 실행 금지 — measure.sh 서버 기동 포트 충돌·자원 경합에 의한 교차 오염 방지, EXP-007 교훈). **교차 순서**로 시점 편향 완화: sol-2 → qwen-2 → kimi-2 → sol-3 → qwen-3 → kimi-3
- **선행 게이트**: 진행 중인 EXP-015 본 run 종료 + 재검증 완료 후 시작 (오케스트레이터가 `done-solar-1` + `go` 신호 대기)
- **run별 usage 분리**: 각 run 종료 시 세션 디렉토리(claude projects / codex sessions)를 run별로 격리 이동 후 파싱 (기존 run 1 세션은 사전 격리)
- **판정 기준 (사전 등록)**: 검증(추가 6 run 전부 완주 — 세 조건 완주율 3/3) / 부분 검증(일부 조건만 3/3 — 조건별 완주율 보고) / run 단위 보류(모델 외적 장애 — 해당 run 재실행 없이 사유 기록)
- **계측**: run별 wall-clock·iteration·커밋·usage. n=3이 되어도 조건 간 효율 비교는 계측 방식 차이(jsonl vs rollout)로 유보 — 완주율과 조건 내 분포만 보고

## 리스크

- 원 실험과 시점이 다르다(4–8일 후) — 서빙 변동이 완주율에 섞일 수 있음, 시점 명기로 관리
- 총 6 run 순차 실행으로 장시간 소요(수 시간) — 오케스트레이터 로그로 진행 추적, run 사이 개입 금지
- Moonshot·DashScope·OpenAI rate limit/장애 시 해당 run 보류 처리 (조건별 판정에는 나머지 run 사용)
