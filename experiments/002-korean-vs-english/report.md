# EXP-002 결과 보고: 한국어 vs 영어 파이프라인 토큰 비교

- 실험일: 2026-07-21
- 가설: [L-01](../../hypotheses/catalog.md) — 전 파이프라인 영어 진행이 한국어 대비 billable 토큰을 유의미하게 줄인다
- **판정: 보류** — 사전 등록한 판정 규칙(|KO평균−EN평균| > 조건 내 run 간 변동폭)을 충족하지 못함. 언어 효과(평균 차 29K)가 run 간 궤적 변동(최대 138K)에 묻힘

## 측정 결과

4 run 모두 완료 기준(Hurl 13파일/154요청 100%) 통과 — 유효 비교 성립.

| 지표 | ko-1 | ko-2 | en-1 | en-2 |
|------|-----:|-----:|-----:|-----:|
| 소요 시간 | 8분 | 8분 | 6분 | 7분 |
| messages | 84 | 82 | 70 | 94 |
| output_tokens | 79,369 | 91,156 | 47,320 | 88,659 |
| cache_creation | 190,827 | 215,084 | 143,453 | 240,190 |
| **billable** | **270,352** | **307,930** | **190,907** | **329,020** |

| 조건 | billable 평균 | 조건 내 변동폭 |
|------|-------------:|---------------:|
| KO | 289,141 | 37,578 |
| EN | 259,964 | **138,113** |

- 평균 차: KO − EN = 29,177 (KO가 10% 많음, 방향은 가설과 일치)
- 판정 규칙: 29,177 < 138,113 → **효과를 노이즈와 구분할 수 없음 → 보류**

## 정적 기준선과의 대조

[static-measurement.md](static-measurement.md): 동일 내용 문서쌍의 KO/EN 토큰 비율은 **산문 2.76배, 표·코드 혼합 1.39배**. 즉 언어 효과는 실재하며 방향도 관측과 일치(첫 쌍 ko-1/en-1 = 1.42)했다. 그러나:

- 실제 작업의 산출물 대부분이 **코드(언어 중립)**라 언어 종속 텍스트의 비중이 작고,
- **에이전트 궤적 변동이 언어 효과보다 크다.** en-2는 스펙 엣지케이스(tagList 부분 업데이트, updatedAt 밀리초 충돌 등)를 가장 깊게 파고들어 4 run 중 최다 메시지(94)·최고 billable(329K)을 기록 — 같은 EN 조건인 en-1(191K)과 1.7배 차이. 무엇을 얼마나 검증하기로 '결심'하는지가 언어보다 큰 비용 변수였다.

## 관찰

- **언어 준수**: KO 2 run, en-1은 완전 준수. en-2는 코드·커밋·README는 영어였으나 **최종 보고문을 한국어로 작성**(부분 미준수, output 소폭 상향 요인). 언어 지시가 세션 말미까지 완전히 유지되지 않는 사례.
- output만 보면 KO 평균 85.3K vs EN 평균 68.0K (1.25배) — 언어 효과의 흔적은 output에서 가장 뚜렷하나, 역시 en-2 궤적에 희석됨.
- 4 run 모두 1 이터레이션·6–8분 완주. EXP-001 ralph(14분, 325K)보다 전반적으로 빠르고 저렴 — Hurl 테스트 경로를 프롬프트에 명시(사전 고정)한 효과로 추정.

## 한계와 후속

- **n=2로는 부족.** run 간 변동폭(EN 138K)이 커서 언어 효과(약 30K, 약 10%)를 판별하려면 조건당 n≥5 수준이 필요할 것으로 추정.
- 코드 비중이 높은 과제 특성상 언어 효과 상한이 낮다. **문서 작성 비중이 큰 과제**(예: 기술 문서·설계서 산출)로 재실험하면 정적 기준선(산문 2.76배)에 가까운 효과가 나올 가능성 → 후속 실험 후보.
- 언어 지시 준수가 완전하지 않음(en-2) — 후속 실험에서는 준수를 시스템 프롬프트 수준에서 강제하거나 준수율을 정량 측정할 것.
