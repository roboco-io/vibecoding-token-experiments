# EXP-002: 한국어 vs 영어 파이프라인 토큰 비교

> 실행 절차: [protocol.md](protocol.md) · 초기 프롬프트: [prompts/](prompts/)

## 가설

[L-01](../../hypotheses/catalog.md): 동일 과제를 전 파이프라인 영어로 진행하면 한국어 대비 billable 토큰이 유의미하게 적다.

근거: Claude 토크나이저에서 한국어는 같은 의미 표현에 영어보다 대체로 1.5–2.5배 토큰을 사용한다. 토큰 차이는 에이전트가 생산하는 텍스트(보고·문서·주석·커밋 메시지)와 재독(컨텍스트 편입)에서 누적된다.

## 과제·워크플로

[realworld-backend](../../tasks/realworld-backend/) — EXP-001의 ralph-loop 단일 세션 워크플로 재사용 (조건당 예측 가능한 약 33만 토큰, 완료 판정 검증됨).

## 조건 (Conditions)

| 조건 | 프롬프트 | 산출물 언어 지시 | runs |
|------|---------|----------------|------|
| KO | [prompts/ko.md](prompts/ko.md) — EXP-001 한국어 프롬프트 + 언어 지시 | 모든 문서·주석·커밋·보고 한국어 | `runs/ko-1/`, `runs/ko-2/` |
| EN | [prompts/en.md](prompts/en.md) — 위의 충실한 영어 번역 + 언어 지시 | all docs/comments/commits/reports in English | `runs/en-1/`, `runs/en-2/` |

- **전 파이프라인 언어 통일**: 프롬프트뿐 아니라 에이전트가 생산하는 모든 텍스트의 언어를 조건별로 강제한다.
- **n=2**: run 간 변동과 언어 효과를 구분하기 위해 조건당 2회.
- EXP-001 ralph 실행은 언어 지시가 없었으므로(주석·커밋이 영어 혼재) KO 조건으로 재사용하지 않는다. 4회 모두 신규 실행.

## 통제 변수

- 모델: Claude Opus 고정, `env -u ANTHROPIC_API_KEY`(EXP-001 인증 사고 재발 방지)
- run별 독립된 빈 작업 리포: `realworld-exp002-{ko,en}-{1,2}` (세션 로그 슬러그 분리 → run별 집계)
- **완료 판정 사전 고정**: 공식 RealWorld Hurl 테스트 154요청 100% 통과 (EXP-001의 테스트 정본 불일치 교훈). 컬렉션 출처는 프롬프트에 명시
- 실험자 개입: 무개입 원칙. 두 프롬프트는 언어 외 내용 동일(번역 충실성은 protocol의 교차 검토 절차로 확보)

## 측정 방법

1. **동적**: run별 세션 로그 집계(`scripts/aggregate_tokens.py`) — billable을 output / cache_creation으로 분해. 산출 문서 샘플 검사로 언어 지시 준수 확인(미준수 run은 무효)
2. **정적 (기준선)**: 동일 내용 KO/EN 문서쌍의 토큰 수 비율 측정 — count_tokens API 사용(유효 키 필요, 불가 시 대체 토크나이저 근사 + 한계 명시). 대상: 프롬프트 번역쌍, EXP-001 plan.md 발췌 번역쌍

## 분석 계획

언어 효과의 발생 위치를 분리한다:

- (a) **output 토큰** — 에이전트 생산 텍스트. 언어 효과가 가장 직접 나타날 위치
- (b) **cache_creation** — 읽은 문서·도구 출력의 컨텍스트 편입. 자기 산출물 재독 시 언어 효과 2차 반영
- (c) **코드 자체** — 언어 무관이어야 정상 (식별자·구문은 영어)

KO/EN 차이가 정적 비율로 설명되는 크기인지, run 간 변동(n=2 범위)보다 큰지 판정한다.

- 언어 간 billable 평균 차이가 같은 조건 run 간 변동폭을 넘으면 L-01 판정 (검증/기각)
