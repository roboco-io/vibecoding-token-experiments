# EXP-007 결과 보고: Solar Open 2 미완주 원인 부검

- 실험일: 2026-07-27
- 가설: [M-03](../../hypotheses/catalog.md) — EXP-006(Solar Open 2) 미완주는 수렴 속도 단일 병목이 아니라 복수 실패 요인(모델 행동 결함 · 실험 환경 오염 · 계측 왜곡)의 중첩이다.
- **판정: 검증** — 3계층 실증: ① 계측 왜곡(usage 3.07배 과대 계상 — 실제 483요청·23.3M input, 추정 ~$3.8로 Opus $6.41보다 낮음), ② 환경 오염(superpowers 훅·글로벌 CLAUDE.md 주입으로 최소 3 iteration 잠식), ③ 모델 행동 결함(선언-실행 탈락으로 커밋 0회, thinking-only 잘림 25회, 과제 이탈 환각 2건).

## 계층 1 — 계측 왜곡: EXP-006 usage는 3.07배 과대 계상

Claude Code 세션 JSONL은 한 API 응답(message)을 콘텐츠 블록별 여러 행으로 기록하며, **같은 `message.id`의 행들이 동일한 usage를 반복 수록**한다(다중 행 message 459개 전수 검증, 459/459 동일). EXP-006 meta.md의 집계는 행 단위 합산이었다.

| 지표 | EXP-006 보고 (행 합산) | 재집계 (message.id dedup) | 배율 |
|------|------------------------|---------------------------|------|
| API 요청 | 1,481 | **483** | 3.07× |
| input | 67.0M | **23.3M** | 2.9× |
| output | 1.30M | **0.50M** | 2.6× |
| 추정 비용 (solar-pro3 단가 가정) | $10.8 | **~$3.8** | — |

**함의**: EXP-006 report의 "보수 추정만으로 미완주 상태에서 Opus 완주 비용($6.41)을 초과" 서술은 성립하지 않는다. 재집계 기준 solar-open2는 15 iteration을 쓰고도 Opus 완주 비용의 약 60%였다(단가 미공개·캐시 미보고라 여전히 추정치). 미완주라 직접 비교는 무의미하지만, "비용 우위가 애초에 없다"는 방향의 근거는 소멸했다. EXP-006 report에 정정 노트를 추가했다.

## 계층 2 — 환경 오염: 실험자 글로벌 환경이 매 iteration 주입됨

open2-2의 모든 세션에 실험자 개인 환경이 주입됐다: **superpowers 플러그인의 SessionStart 훅**("1%라도 해당하면 스킬을 반드시 호출하라") + **글로벌 `~/.claude/CLAUDE.md`**("선택·확인이 필요하면 AskUserQuestion을 호출하라"). 무개입 자율 루프와 정면충돌하는 지시들이다. 모델은 이를 문자대로 따랐다:

- **B2-3, B2-9** (2 iteration): `superpowers:using-superpowers` + `superpowers:brainstorming` 호출 → "설계를 제시하고 **승인을 받겠습니다**"라며 설계 문서만 쓰고 종료. 편집 0.
- **B3-2** (마지막 iteration): 10개 파일 실패의 5대 원인을 정확히 진단한 뒤, 수정 대신 글로벌 규칙대로 `AskUserQuestion` 호출 → headless에서 도구 비활성 오류 → iteration 소모. 진단 내용(Fastify 헤더 소문자 정규화, PUT /api/user 422 미반환, favorites 500, tags 포맷, body 누락)은 정확했다는 점이 뼈아프다.
- B1-1에서 서브에이전트 3회 파견(Explore·general-purpose) — superpowers 지시 준수 행동으로, 컨텍스트 비대화에 기여.

정량: 15세션 중 kill 유실 2개를 뺀 13개 중 **최소 3개(약 23%)가 오염 지시 준수로 잠식**됐다. EXP-005의 "허락-대기" 실패 모드도 동일 오염 환경에서 관찰된 것으로, 순수 모델 귀책이라 단정할 수 없게 됐다. (Opus 기준선 EXP-002도 같은 환경이었으나 Opus는 주입 지시에 정지하지 않았다 — 오염은 "주입 컨텍스트에 대한 강건성"이라는 모델 특성을 드러낸 셈.)

## 계층 3 — 모델 행동 결함 (모델 귀책)

1. **선언-실행 탈락 (announce-then-drop)**: "이제 첫 번째 커밋을 남기겠습니다"를 4회 이상 선언, `git add`를 2회 실행(스테이징까지 도달)하고 **`git commit` 시도는 15세션 전체에서 0회**. 지시 무시가 아니라 계획을 선언한 뒤 실행 단계에서 탈락하는 패턴. 무편집 iteration 3개(B2-1 0.3분, B2-3 0.8분, B2-5 8.3분)도 "…하겠습니다" 선언 후 end_turn으로 종료.
2. **thinking 폭주**: 483개 응답 전부에 thinking 블록, 문자 수 기준 출력의 **95%가 thinking**(1.33M자 vs 텍스트 6.5만자). 그중 **25회는 thinking만 생성하다 max_tokens로 잘려**(B2-2에 13회 집중) 도구 호출 0의 순수 낭비 API 호출이 됐다.
3. **과제 이탈 환각**: B2-8에서 과제와 무관한 "Render Redis 캐시 도입" 컨설팅 답변(존재하지 않는 `buildShardIndices()` 등)을 생성. B2-6에서는 macOS 환경에서 Windows cmd 오류 메시지("'fastify'이(가) 내부 또는 외부 명령…")를 포함한 가짜 터미널 출력을 생성. `</think>` 태그 텍스트 누출 1회(B2-10).
4. **수렴 자체는 실재하나 종반 도약**: full-suite 궤적은 1/13(B2-8, 00:16)에서 4 iteration 정체 후 3/13(B3-1, 06:26)으로 도약, 요청 실행 64→94. 마지막 iteration은 위 오염(질문 시도)으로 소모.

## 결론·후속

- **"수렴 속도 병목" 단일 서사는 기각.** 미완주는 (a) 자율 루프를 방해하는 주입 지시에 대한 취약성, (b) 선언-실행 탈락·thinking 폭주라는 모델 결함, (c) 여기에 외부 kill 2회가 겹친 결과이고, 비용 초과 서사는 계측 오류였다. 13개 유효 iteration 중 무편집·오염·유실을 빼면 실작업 iteration은 약 8개였다.
- **Phase B 권고** (실행 여부는 별도 결정): 오염 제거(격리 `CLAUDE_CONFIG_DIR`로 플러그인·글로벌 CLAUDE.md 미주입) + `.ralph-done` 외부 검증 게이트 + 상한 30 iter + 매 iteration 종료 시 Hurl 자동 실행(수렴 곡선 직접 계측). 오염 제거만으로 iteration 낭비 약 23%가 회수되고, 마지막 iteration의 정확한 진단이 실행으로 이어졌을 가능성을 검증할 수 있다.
- 분석 스크립트: [scripts/analyze_transcripts.py](scripts/analyze_transcripts.py) (표준 라이브러리만, EXP-006 로그 대상 재실행 가능)
